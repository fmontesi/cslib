# Concurrency traces: development handoff

Last updated: 2026-11-03

## Current state

`Basic.lean` defines `Independence I` as a class abbreviation combining `Std.Symm I` and
`Std.Irrefl I` for a relation `I`. `List.PermUpTo r` is the equivalence of lists generated by
swapping adjacent elements related by `r`, and specializes to trace equivalence when `r` is an
independence relation. It has `nil`, `cons`, `swap`, and `trans` constructors, like `List.Perm`;
reflexivity, symmetry, and compatibility with appending are proved separately. The `swap` case
accepts `r a b ∨ r b a`, preserving the original equivalence for asymmetric relations too.
`Trace` is the quotient by this relation; `Trace.mul`,
`Trace.toLanguage`, and `Representative` use it.

The trace equivalence representation has not been changed to use a relation closure.

## Findings

- `List.Perm` alone is too permissive: it allows dependent actions to cross. If distinct `a`
  and `b` are dependent, `[a, b]` and `[b, a]` are permutations but are not trace equivalent.
- `List.PermUpTo` implies `List.Perm`; a bridge theorem would make the permutation API
  available to clients.
- A targeted search of the project's Mathlib checkout did not find a list permutation relation
  parameterized by allowed swaps. This is not a conclusive absence claim: the Lean MCP search
  index was still warming. `List.rel_perm` transports permutations across a pointwise relation;
  it does not restrict which elements may be swapped.
- Mathlib's `Relation.ReflTransGen` provides a potentially useful general construction: the
  reflexive-transitive closure of a one-step relation. See
  [Mathlib's relation API](https://leanprover-community.github.io/mathlib4_docs/Mathlib/Logic/Relation.html).
- The chosen representation of independence uses the two `Std` relation classes directly.
  The user explicitly ruled out representing independence with a graph.

## Candidate refactor

Define a one-step relation that swaps two adjacent independent actions in an arbitrary prefix
and suffix, and define `List.PermUpTo` as its `Relation.EqvGen` closure. An equivalence closure
works for arbitrary relations, including asymmetric ones; alternatively, a reflexive-transitive
closure of a symmetric one-step relation would work. This should describe the same relation as
the existing inductive definition, but that equivalence has not yet been proved. This is a
proposal, not an agreed or implemented change.
